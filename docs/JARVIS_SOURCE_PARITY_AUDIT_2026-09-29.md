# JARVIS source parity audit — 29 September 2026

This compares the implementation under `../JV2/jarvis-main` with ORION code, rather than treating either README as proof of a working feature. JARVIS was read only. “Present” means an ORION implementation exists; it does not assert that every external service or physical device was available during this audit.

## Change verified in this pass

`vision_analyse` now accepts `action="watch_camera"`, `seconds` (default 6, bounded 2–15), `frames` (default 6, bounded 2–8), optional `camera_index`, and a focus `prompt`. Capture runs off the event loop. It uses one camera handle for the sequence, or borrows an already-open face-tracker stream; it does not save a video file. A labelled contact sheet costs one vision call for the whole movement, respecting the user's low request-per-minute limits. The reply names capture failures instead of claiming to have watched. The model prompt says there is no audio, so speech is not inferred from silent frames.

Focused verification: `tests/test_jarvis_webcam_watch.py`, `tests/test_video_analysis.py` and `tests/test_parallel_execution.py` — **114 passed** on 29 September 2026. Tests cover ordered-frame reasoning, one model call for the contact sheet, bounded arguments, failure reporting, borrowed-camera use without a second handle, and tool/schema scheduling. A physical webcam movement test remains to be done on the PC.

## Additional desktop parity work

Retrospective analysis requires the user to start local camera watching first. The perception loop samples no faster than once a second into a 16-frame, 15-second in-memory ring. `vision_analyse(action="watch_camera_past", seconds=10, prompt="what just happened?")` reuses the ordered-frame analysis and a single vision call. Stopping the watch erases the ring. Hand pointer mode is explicit and mutually exclusive with media and orb gestures; the existing autonomy switch still guards input. Double-clap wake is off by default and requires both `ORION_WAKE_MODE=1` and `ORION_CLAP_WAKE=1` before the existing microphone gate considers it. None of these changes have been validated against a physical webcam or the user's room acoustics.
