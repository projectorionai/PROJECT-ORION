# ORION audit — 3 October 2026

This audit follows the [25 September execution plan](../EXECUTION_PLAN.md) on
the Mark XXXII source. It records what was examined, every defect that was
reproduced and fixed, the roadmap capabilities that were found missing and
added, and what was examined but deliberately left alone.

Most defects below were reproduced against running code; the rest were found
by reading code against its own documentation, and the "How it was found"
column says which. Every fix has a regression test that fails on the original
code. Where a claim rests on something weaker, the text says so.

## How the evidence was gathered

| Method | What it covered |
| --- | --- |
| Full test suite, before and after | Linux, Python 3.13, Qt offscreen, 8 parallel workers |
| Static analysis | `ruff` (pyflakes, bugbear, async rules), `bandit` (medium and high), with every hit read by hand |
| Headless node, driven over HTTP | Boot, pair a device, mint a token, chat, `/v1/agent/tasks`, malformed bodies, path traversal |
| Desktop app, booted offscreen | Boot with asyncio debug on; Ctrl+C sent at 1–12 s into the run, repeatedly |
| Tool sweep | The real desktop composition booted with a copy of the repository, then **every declared tool called with no arguments and with each of its declared actions: 632 calls** |
| Dependency resolution | `pip install -r requirements.txt` resolved on Linux |
| File permissions | Mode bits of every credential file a fresh node writes |

The tool sweep found **no unhandled exception and no hang** in 632 calls: the
dispatcher's error handling is sound. What it did find were tools that act on
the wrong target when an argument is missing, and one handler that blocks the
GUI thread. Those are below.

## Defects found and fixed

| # | Defect | How it was found | Fix |
| --- | --- | --- | --- |
| 1 | **Ctrl+C was ignored in about half of all runs.** Under Qt 6, `QApplication.quit()` first offers every window a close event and abandons the quit if one refuses, and several ORION windows refuse by design (they hide to the tray). | SIGINT sweep: 4 of 6 runs still alive 35 s later; a stack dump showed the loop idle in `run_forever` | Ctrl+C now calls `app.exit(0)`, which ends the loop unconditionally and still emits `aboutToQuit`. A quit that arrives before shutdown handling is wired during boot is now latched and honoured. After: 7 of 7 runs exit within 2 s. |
| 2 | **Backups failed whenever the config folder had been moved**, which is the recommended setup (`tools/move_config.py`): every backup failed with "is not in the subpath of", leaving a partial zip behind. | Tool sweep | Archive entries are named relative to the config directory, and archives are written to `.part` and renamed only when complete. |
| 3 | **Backups put every credential into a cloud-synced folder.** API keys, the uplink's token-signing key, its TLS private key, Twilio and bot tokens, MCP credentials and logged-in browser sessions went into an archive whose default destination is OneDrive. This contradicts the project's own key-store policy in `constants.py`. | Reading the backup path after #2 | Credentials and sessions are withheld (listed in `WITHHELD_SECRETS.txt` inside the archive); `ORION_BACKUP_SECRETS=1` includes them for a trusted destination. Caches and downloaded models are skipped. |
| 4 | **Backups copied live SQLite files raw**, `-wal` and `-shm` included, while ORION was writing to them. | Reading the backup path | Each store is copied with SQLite's backup API. A test proves a WAL-only row reaches the archive and the copy passes `integrity_check`. A backup that could read nothing is now reported as a failure. |
| 5 | **The uplink's token-signing key and TLS private key were world-readable** (0644) on a headless Linux node, beside 0600 siblings. Whoever can read the key can mint an access token for any paired device. | Mode bits after a fresh boot | Both are written owner-only, and an existing key is tightened in place without being rotated. |
| 6 | **Behind the deploy guide's Caddy proxy, every phone shared one rate-limit bucket**, so ten bad pairing attempts from anywhere locked the owner out of token refresh for a minute. | Reading `_client_key` against `deploy/Caddyfile` | `X-Forwarded-For` is believed only from loopback (or `ORION_TRUSTED_PROXIES`), and the right-most hop is used. |
| 7 | **The headless node could not run any remote tool**: every `/v1/agent/tasks` call answered 503 "no dispatcher wired on this node", even the read-only whitelisted ones. | HTTP probe | New `HeadlessToolHost` runs the read-only remote tools through the desktop's own handlers. |
| 8 | **With no model reachable, the headless node answered every chat turn with 502**, while holding 88 knowledge entries it had seeded a second earlier. | HTTP probe | The node builds its gated LocalBrain, and LocalBrain now answers general questions from the seeded programming, security and business knowledge. An answer is given only when the entry's own title shares a word with the question, and it can be corrected ("no, that's wrong…"). |
| 9 | **The node asked the phone to approve actions it could never perform** ("open notepad" was parked for confirmation on a machine with no desktop). | HTTP probe after #7 | A dispatcher can declare `can_run`; the gate answers "needs the desktop" instead of parking. |
| 10 | **"What's new?" described a July release.** The patch-notes changelog stopped at X.7 (14 July) while the package shipped Mark XXXII; `find("31")` and `find("XXXI")` found nothing. | `patch_notes` on the node | Marks XXX–XXXII added, dated only from evidence in the repository; lookup matches versions and whole codename words. A test ties the newest entry to `__version__`. |
| 11 | **`code_changes` froze ORION for 2.6–2.8 s.** It is a synchronous handler that parses every module on the qasync loop, which is the GUI and voice thread. | Tool sweep timings | Runs in a worker thread. No other synchronous handler exceeded 60 ms. |
| 12 | **`learn` with the folder left out ingested ORION's own source tree** as 6,662 "facts" from 856 files (`Path("")` is `.`, the project). | Tool sweep | Asks which folder. |
| 13 | **The file-dialog step typed a path and pressed Enter with no dialog open.** Its own output read "Submitted … No open dialogs or pop-ups detected." Typing goes to whatever has focus, so this could post into a chat or submit a form. | Tool sweep | It types only into a detected dialog, and needs a path. `upload` was added to the dialog detector so Firefox's "File Upload" is recognised. |
| 14 | `about:blank` was rewritten to the unloadable `https://about:blank`. | Tool sweep | Recognised before the scheme is added. |
| 15 | `file_controller` write/append/delete/mkdir with no path targeted the project root (write failed with "Is a directory"; delete was refused only because the root is not empty). | Tool sweep | Mutating actions need an explicit path. |
| 16 | **`requirements.txt` could not be installed off Windows**: `pywin32` and the `winrt-*` packages publish Windows wheels only. | `pip install --dry-run` on Linux | Platform markers on the ten Windows-only packages. Resolves on Linux; Windows unchanged. |
| 17 | **The pairing QR never appeared on a fresh install**: `qrcode` was imported but not declared. | Reading the Security Centre against the requirements | Declared. |
| 18 | **`deploy/sync_state.sh` could push under a running node.** It stopped a unit called `orion`, but the Oracle guide installs `orion-node`, so the stop failed, the script warned "continuing", and then replaced databases under the live service. | Reading the script against both deploy guides | Finds `orion` or `orion-node` (or `ORION_REMOTE_UNIT`), and refuses to push if it cannot stop the node unless `ORION_FORCE=1`. |
| 19 | `sync_state.sh` read and wrote `<repo>/config` even after the config had been moved, and shipped `second_brain.db`, which no version of ORION writes (the second brain is `knowledge_graph.db`). | As above | Uses `ORION_CONFIG_DIR`, then `config_location.txt`, then `config/` (new `where` mode prints it); ships `knowledge_graph.db`, `evidence_graph.db` and `ingestion.db`. |
| 20 | The headless node never ran the periodic WAL checkpoint or the final checkpoint at shutdown that the desktop runs for durability. | Comparing `server.py` with `app.py` | Both now run on the node. |
| 21 | Off Windows, the cursor halo retried a failed `import pyautogui` 33 times a second (95 µs a call) on the face's thread. | `test_gui_hot_paths` failing even when run alone | Uses Qt's own cursor position. |
| 22 | Two tracebacks printed after "ORION has shutdown cleanly.": a telemetry step resumed after the loop stopped, and a deleted animation timer. | Shutdown logs from #1 | Both are guarded. |

### Documentation that was wrong

- `deploy/README_ORACLE_CLOUD.md` §8 told people to point both nodes at one
  rclone-synced `config/`, the exact setup `sync_state.sh` and the capabilities
  summary say silently corrupts SQLite. §7 and the quick test still described the
  retired static token. Both are rewritten.
- `server.py`'s docstring said a node and a desktop "can share a config directory
  (or a synced volume)". Corrected.
- The Hostinger guide led with raw `rsync` of live databases and listed
  `second_brain.db`. It now leads with `sync_state.sh`.
- `docs/capability_baseline.json` lagged the code by five tools (`aviation`,
  `fetch_url`, `find_tool`, `sound_sense`, `use_tool`). It is refreshed; nothing was
  removed.

## Capabilities that were promised but missing, now added

| Capability | Where it was promised | What exists now |
| --- | --- | --- |
| **Remote audit log** | Cloud Roadmap C4: "a durable audit log (who/when/what tool/what result) surfaced in the Command Centre, not just a log line" | `remote_audit.py` writes `diagnostics/remote_audit.jsonl`, capped and rotated. It records pairings, refused tokens, revocations, agent tasks, every tool a phone's turn ran through the gate, and every approval or refusal. Argument names are kept; argument values, chat text and results never are. Shown in the Security Centre; "what has my phone been doing" (`system_startup` action `phone_activity`). |
| **Conflict-aware scheduling** | Improvements brief §2.4: "find me 90 minutes this week for X" across calendars, never auto-booking | The engine (`scheduling.py`) existed and was tested but was never called. `calendar_sources.py` now reads busy time from ICS feeds (`config/calendars.json`: Google, Outlook.com, Microsoft 365, iCloud), the Outlook desktop calendar (COM, recurrences expanded, attach-only) and Notion. `executive` actions `find_time` and `book_slot` propose up to three slots and name every calendar that could not be read; nothing is booked until "book option N". |
| **Headless node remote tools and offline answers** | Implied by the C4 whitelist and the node's purpose | See defects #7–#9. |
| **Node health pings** | Brief §4.2: "nothing currently *watches* it" | `ORION_HEALTHCHECK_URL`: pinged every `ORION_HEALTHCHECK_MINUTES`; a failure is logged once, as is the recovery. |
| **Scheduled node backups** | Brief §4.2: "no documented backup strategy on the cloud node" | `ORION_NODE_BACKUP_DIR` and `ORION_NODE_BACKUP_HOURS`, using the repaired BackupManager. |

The ICS reader handles what real calendars emit: folded lines, UTC, zoned and
floating times (including Outlook's Windows zone names), all-day entries,
`DURATION`, `RRULE` (DAILY; WEEKLY with BYDAY; MONTHLY by date or by ordinal
weekday such as "last Friday"; YEARLY; with INTERVAL, COUNT and UNTIL), `EXDATE`
and moved occurrences. Free, transparent and cancelled entries do not block
time. An all-day entry blocks time only when it is marked busy or out of office.
A recurring series that began years ago is fast-forwarded to the search window
rather than expanded from its start.

## Examined and deliberately not changed

1. **Android: first contact, token storage, background delivery, native speech.**
   Out-of-band certificate fingerprints, Keystore-wrapped refresh tokens, a
   foreground service and native `SpeechRecognizer` are all still open. None can
   be built or tested in this environment (there is no Android SDK, and the APK
   workflow runs only on `main`). Writing Kotlin that has never compiled would
   be a guess.
2. **Wall-clock tests.** `test_holo_head::test_paint_stays_within_the_frame_budget`,
   `test_no_lag_gate::test_the_face_paint_stays_inside_a_frame`,
   `test_perception::…reduces_without_converting_every_pixel` and
   `test_performance_scale::test_deck_listing_stays_flat` measure elapsed time
   and fail intermittently under 8 parallel workers. All pass run alone.
3. **Slow boot steps under asyncio debug.** Several boot phases held the loop for
   1–2.6 s under `-X dev` with asyncio debug in this container, which inflates
   every step. Without debug, boot reached its idle wait in 1.7 s. As the last
   plan said, judge these on real hardware with ORION's own stall detector.
4. **Static-analysis hits that are not defects.** Bandit's 22 "SQL injection"
   findings are all placeholder-parameterised queries with fixed identifiers.
   Its SHA-1/MD5 findings are content fingerprints, not security uses. Ruff's
   undefined names were string annotations (now imported properly anyway).
5. **The single-instance lock socket** shows a `ResourceWarning` at exit under
   `python -X dev` only. The kernel frees an abstract-namespace socket on exit.
6. **Sentinel soft-duplicates** (`sentinel.py`, `security_sentinel.py`,
   `system_guard.py`), flagged by the improvements brief, are unchanged. Merging
   them is a design change with no reproduced defect behind it.

## What was not verified

No Windows machine, microphone, camera, phone, provider account, Outlook
installation, Notion workspace, Twilio account or published calendar feed was
used. The Outlook calendar reader is tested against a COM double built to
Outlook's documented `IncludeRecurrences`/`GetFirst`/`GetNext` behaviour, not
against Outlook itself. ICS parsing is tested against fixtures written to the
iCalendar format, not against downloaded feeds. The Windows-only paths changed
here (Ctrl+C, the file-dialog guard) were exercised on Linux and with doubles.

## Using the new behaviour

- **Find time:** "find me 90 minutes this week for the proposal", then "book
  option 2". To read other calendars, create `config/calendars.json`:
  `{"ics": ["https://…/basic.ics"]}`. Outlook is read when it is running.
- **Remote activity:** "what has my phone been doing?", or the Security Centre's
  activity list.
- **Backups:** unchanged commands. Credentials are now left out unless
  `ORION_BACKUP_SECRETS=1`; the archive's `WITHHELD_SECRETS.txt` lists what was
  left out.
- **Headless node:** `ORION_HEALTHCHECK_URL`, `ORION_NODE_BACKUP_DIR` (see the
  Oracle guide §9). Behind a proxy on another host, set `ORION_TRUSTED_PROXIES`.
- **Sync:** `bash deploy/sync_state.sh where` shows which data folder it will use.
